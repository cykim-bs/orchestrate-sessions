# 일별 모델·추론 수준 (Model & Effort by Task)

비용 대부분은 대화 맥락의 크기에서 나온다. 매 턴 지금까지의 대화를 다시 읽기 때문이다.
그래서 추론 수준만 낮추기보다 **단계가 바뀔 때 큰 맥락을 끊고, 그 단계에 맞는 모델로 넘기는 것**이 효과가 크다.

## 에이전트가 정하는 곳

세션을 띄우거나(`start_session`의 `model`·`effort`) 서브에이전트를 부를 때(Agent 도구 `model`) 아래 표대로 준다. 사용자가 그 요청에서 모델·수준을 말하면 그쪽이 우선한다.

| 일 | 모델 · 추론 수준 |
|---|---|
| 기획·설계, 원인 모를 버그, 여러 저장소에 걸친 판단 | Opus xhigh (아주 어려우면 가장 강한 모델 high) |
| 기능 구현 | Opus high, 작은 수정은 medium |
| 문서·웹 조사, 리서치 정리 | Opus medium~high |
| 코드·파일 찾기, 기록·로그 분석 | Sonnet medium (단순 검색은 Haiku) |
| 빌드·배포, 테스트 돌리기, 보고 보내기 | Sonnet medium (막히면 Opus) |
| git: 단위별 커밋 | 그 단위를 구현한 세션이 함께 |
| git: push·rebase | Sonnet medium (보고 세션과 묶음) |
| 여러 세션 지휘 | Opus high |

- **여러 단계를 서브 세션으로 나눠 맡기라는 요청**(「서브세션으로 나눠서」, 「세션 나눠서 시켜」, 「지휘해줘」)에는 `orchestrate-sessions` 스킬을 따른다.
- Agent 도구의 `model`은 보통 별칭(`sonnet`·`haiku`·`opus`)만 받는다. 추론 수준은 세션 `effort`나 에이전트 정의의 `effort`로 정한다.
- 판단이 필요한 리뷰·검증 서브에이전트는 부모 모델을 그대로 쓴다.

## 한 세션 안에서

- **같은 세션에서 모델을 바꾸지 않는다.** 모델마다 캐시가 따로라, 바꾸는 순간 지금까지의 맥락 전체를 비싼 값으로 다시 읽는다. 예외는 맥락이 작을 때(대략 5만 토큰 이하)나 1시간 넘게 쉬어 캐시가 이미 식었을 때다.
- **추론 수준은 바꿔도 된다.** 최근 모델은 수준을 바꿔도 캐시가 유지된다. 커밋·푸시·값 확인 같은 기계적인 단계는 낮게, 어려운 턴만 높인다.
- 에이전트는 자기 모델·수준을 바꿀 수 없다. 지금 단계에 맞지 않으면 사용자에게 한 줄로 제안한다(예: 「여기부터는 medium이면 충분합니다」).
- 구현이 끝나고 빌드·보고처럼 큰 맥락이 필요 없는 단계가 길게 남으면, 짧은 인수인계 문서를 써서 가벼운 모델의 서브에이전트나 새 세션에 맡긴다. 맥락이 큰 세션에서 그대로 이어 가지 않는다.
