# 서브 세션 브리프 틀

브리프는 대화를 전혀 못 본 세션이 읽는 유일한 설명서다. 세션 도구가 할 일(`prompt`)과 배경(`background`)을 나눠 받으면 나눠 쓴다.
앞 단계 산출물은 **경로로 가리키고** 내용을 다시 붙이지 않는다. 브리프가 길수록 세션마다 같은 토큰을 다시 낸다.

## prompt (할 일)

```text
<한 문장: 이 세션이 할 일과 범위. 다음 세션 몫(하지 않을 단계)도 적는다.>

**읽을 것(정본)**: <작업 폴더>/<파일>의 <절>. 계획과 다르게 해야 하면 이유를 결과 문서에 적고 진행한다.

**작업 장소**: <절대 경로>에서만 한다. <git pull 여부, 브랜치>.
<공유 자원이 있으면: 잠금 → 작업 → 커밋 → 잠금 해제 순서>

**허락(사용자 원문·날짜)**: 「…」(YYYY-MM-DD). 범위: <파일 하나 / origin <브랜치> push / 발행 안 함>.
범위 밖이 필요하면 멈추고 마지막 답변에 적는다.

**지킬 것**: <이 단계에 걸리는 프로젝트 금지만: 건드리면 안 되는 폴더, 다운로드 금지 등>

**커밋**: <단위별 메시지 형식 / 커밋하지 않음>. push는 하지 않는다(마지막 세션 몫).

**결과 기록**: <result.md의 어느 절, 「다음 세션이 알 것」 절>. 외부 보고는 하지 않는다(마지막 세션 몫).

마지막 답변: <커밋 해시, 완료 기준 통과 여부, 산출물 경로, 남은 문제를 짧게>.
```

## background (배경)

```text
<프로젝트 한 줄 설명(저장소, 언어·프레임워크)>. 사용자 요청(YYYY-MM-DD): 「원문」. 이어서 「…」(허락 원문).
진행(지휘 세션이 단계별로 띄움): ① <단계>(끝남) → ② **이 세션(<모델·수준>)** → ③ <다음 단계와 담당>.
확정된 사실: <커밋 해시, 산출물 경로, 핵심 결정 3~5줄>.
규칙은 <프로젝트 CLAUDE.md 등>. 사용자에게 보이는 답은 <언어>로 짧게.
```

## 띄우기 전 점검

- 대화를 못 본 세션이 이 브리프만으로 끝낼 수 있나(경로, 완료 기준, 마지막 답변 형식).
- 허락 범위가 원문과 날짜로 들어갔나. 허락 없는 push·발행·다운로드·메시지를 시키지 않았나.
- 다른 세션이 같은 파일·폴더를 동시에 쓰지 않나.
