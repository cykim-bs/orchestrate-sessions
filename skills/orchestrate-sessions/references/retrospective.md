# 지휘 회고

목적: 단계별 모델·추론 수준 배정이 맞았는지 보고, `model-effort-by-task` 표를 고칠 근거를 모은다.
지난 세션은 보관(archive)된 경우가 많으니 검색·목록에서 보관된 세션을 포함한다.
세션이 많으면 2~4단계를 가벼운 모델(Sonnet medium)의 서브에이전트에 맡기고 표만 받는다.
아래 도구 이름은 예시다. 실제 도구 설명을 따른다.

1. **지휘 세션 찾기**: 대화 기록 검색(`search_session_transcripts` 등, 보관 포함)으로 「지휘」, 「서브 세션」을 찾는다. 기간·프로젝트 폴더로 좁힌다.
2. **자식 세션 모으기**: 세션 목록(`list_sessions`, 보관 포함)에서 지휘 세션이 띄운 것을 고른다(시작한 세션·부모 세션 정보).
3. **세션별 기록**: 세션 정보(`get_session`)에서 모델·추론 수준·만든 시각·마지막 활동 시각(걸린 시간)을 본다. 최근 이벤트(`list_events`)에서 마지막 결과와 완료 기준·남은 문제를 본다.
4. **재작업 표시**: 같은 단계를 다시 띄웠는지, 지휘가 후속 메시지로 고치게 했는지, 사용자 지적이 있었는지, 지휘가 직접 고친 것이 있는지 적는다.
5. **판정**: 단계마다 「낮춰도 됐다」(재작업 없이 짧게 끝남, 판단이 거의 없음) / 「올렸어야 했다」(재작업·지적·완료 기준 미달) / 「맞음」.
6. **비용 감(선택)**: 사용량 도구는 열린 세션만 보여 줄 수 있다. 세션별 토큰이 꼭 필요하면 `~/.claude/projects/<프로젝트 폴더>/*.jsonl`의 usage 합계를 서브에이전트로 센다.
7. **결과**: 작업 폴더(기본 `.orchestration/YYYYMMDD-orchestration-retro/report.md`)에 세션 표(단계·모델·수준·시간·턴·재작업·판정)와 룰 표 변경 제안을 쓴다. 룰 수정은 사용자 확인 뒤에 한다.
